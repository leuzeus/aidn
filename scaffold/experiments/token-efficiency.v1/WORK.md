# Admitted product work

Apply COMMON.md and the current admitted plan. Group skills already required by
the next plan step in one workflow observation. Fetch complete known plan/status,
requirement and rule units together. Reuse a previously observed exact preimage
only when the actual write admission/CAS independently validates its current
scope and revision. Do not re-read solely to produce a preparation identifier.

After the model chooses and states the next action, a host invocation may execute
already-authorized deterministic preparation and that exact native action in
sequence if both native tools support this composition. Fresh specific admission
and actual PreToolUse must still run at the write. Never emulate a native edit
with a shell write, or precompute a permission for a later independent action.

After an action, group the already-known applicable tests and deterministic
governance controls in dependency order. Inspect every result and retain each
execution. The batch stops on failure; it does not change scope, requirements or
acceptance. Return new evidence to the model for the next decision. A refused
edit requires diagnosis and an explicitly authorized repair followed by fresh
admission; the refused attempt remains in the audit history.
