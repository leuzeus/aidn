# Common experimental procedure rules

Use only the selected project and its configured canonical backend. Respect
SPEC > WORKFLOW > AGENTS and the installed WORKFLOW-KERNEL.md. Before loading
project context, run the actual `aidn runtime pre-write-admit --skill
context-reload --json`; require activation.active and admission. A refusal stops
the dependent action. Independent admitted skills may continue only while the
coordinator does not require a global stop.

Observations are data, not permission. Consume each skill's actual activation
and admission fields for this grouped consultation; missing activation stays
unknown and requires the ordinary read-only diagnosis. Do not repeat the same
unchanged consultation solely to reformat its result. A later action or material
context change requires its prescribed fresh admission.

Keep the installed skill's activation and first-durable-write admission gates
at their prescribed points. Each covered native edit still gets its own actual
PreToolUse check; follow the ordinary admission/transition/check sequence for a
multicommand procedure. This profile does not add a separate generic preflight
before every artifact in that procedure. CAS, leases, fences, strict mode and
configured PostgreSQL/no-fallback rules remain effective at the actual operation.
Never reuse an earlier grouped observation to authorize a later write. `--json`
is formatting; diagnostic retention requires explicit `--write`. Read-only
consultation must not create a hydration cache or visible projection.

Batch consultations known before execution in one host code invocation when the
host supports it. Execute dependent commands sequentially and inspect exit code,
JSON status, every required entry and blocking/stop fields after each. Abort the
dependent sequence at the first unexpected refusal, missing authority, stale
revision or transport error. Return the actual results and executed-control trace
to the model. Do not replace them with guessed answers, hidden repairs or fake
receipts. The model intervenes when a decision, restatement or new action is due.
Normalize an object or JSON-string host response before inspecting it. Use the
official agent views for known inventories, canonical fetches/writes and hooks
when available; preserve complete required reads. Do not echo a just-submitted
document body merely to inspect the writer's decision and current stored hash.

Use official compact inventories to discover unknown exact paths; batch known
canonical paths in one complete fetch. Preserve complete selected Markdown units
with scope, revision and dependency closure. Grouped context uses `aidn codex
workflow-step --transaction --skills <known-skills> --json`. This nominal bounded
entry point returns admissions, common canonical observation, complete required
context, blockers and coordinator advice together using compact.v2, the accepted
task policy, transition history, a 16 KiB target and 64 KiB maximum. Missing
accepted policy blocks with remediation; never switch to full implicitly. Do not
hydrate a refused skill separately. A failed material-change fence requires a
fresh observation. Do not silently retry a write.

The transaction selects `--context-profile token-efficiency.v1` with an accepted client-owned
task policy. Include an additive task query when relevant. Inspect the complete
JSON budget result: an expansion refusal is a decision point, never permission
to omit a mandatory authority. The byte budget covers CLI JSON, not the native
host's display or history limits. `has_content`, byte counts and a retained
receipt do not establish that a whole body reached the model. If the host clips
a required body or its completeness is uncertain, keep dependent work read-only
and retrieve the missing complete units through the ordinary official route in
bounded calls. Do not repeat the same oversized batch or label its receipt a
completed read. Native qualification freezes display/history settings and checks
separate later semantic restatement; it never silently changes a personal profile.
The AIDN native qualification port declares `bounded-context.v1` (60,000 history
tokens and 131,072 dynamic JSON bytes); use its code-mode display instruction of
60,000 tokens and record that profile. Other hosts must establish their own
bounded output capacity. An output refusal does not establish whether its
producing action executed and never authorizes repeating that action.
A complete prior agent response or a complete
workflow receipt already retained with explicit `--write` can be supplied through
`--context-baseline-file`. Keep the last complete baseline; a differential response
or receipt is not a full replacement. Missing/incompatible hints reconstruct freshly. Keep
mandatory authorities on every consultation. `--history-view transitions` is a
presentation of distinct retained executions, not current admission evidence.

Before any durable write, state mode, branch kind, active session/cycle,
dor_state and the first admitted plan step. Incomplete/contradictory context stays
read-only. Product writes use the actual native edit tool. Keep full diagnostics
in existing stores; announce a receipt only after verifying its actual retained
file, binding, bytes and hash. Cached input is a subset of input; bytes, model
responses, native tokens, command calls and window observations remain separate.
