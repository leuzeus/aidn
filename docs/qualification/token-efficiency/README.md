## Response accounting

The internal read-only evidence utility is:

```powershell
node tools/perf/summarize-response-usage.mjs --events <phase-1-native-events.jsonl> --events <phase-2-native-events.jsonl>
```

It counts only `rawResponse/completed` records, deduplicated by thread and
response identity. Conflicting duplicates, invalid numeric counters and unsafe
sums refuse output. Missing counters remain null. Cached input is a subset of
input; reasoning output is a subset of output. Thread lifetime usage and window
pressure are separate observations. Input hashes bind the files actually read,
without proving authenticity or workflow completeness. No byte/token conversion
or financial or causal estimate is made.

Historical replay against both retained AIDN phases of attempt 036 reproduced
119 responses, 13,533,955 input, 13,183,104 cached input, 350,851 uncached input,
40,617 output and 5,104 reasoning output tokens. This validates accounting against
that historical report; it is not the new 0.14.0 reference or an efficiency result.

The required working-memory gate includes the observer and real utility
regressions through `verify-context-metrics-fixtures.mjs`. Native reference logs,
credentials and local infrastructure paths stay outside the repository.

The AIDN arm passed actual native development controls, coordinator relay,

overlapped early reference execution; timings are descriptive observations,
not isolated causal latency estimates. No optimization has been measured yet.

The separate synthetic native read-refusal/repair case passed four actual CLI
calls with retained exit codes `[2, 0, 0, 0]`: deliberately wrong note reference,
complete official inventory, exact complete repaired canonical read and fresh
independent context-reload admission. It used five model responses, 119,545
cumulative input and 29,689 uncached input tokens. It grants no write authority
and does not prove repair of a refused product edit. That separate boundary
remains part of later qualification.

Six successful complete scoped-context fixture responses measured 4,128–6,080
UTF-8 JSON bytes; two blocked cases are excluded from calibration. The initial
experimental target is 16,384 bytes (next power of two above twice the observed
maximum), with a 65,536-byte hard limit. The margins are engineering choices,
not measured guarantees or native-token limits. The manifest retains these
observations and corpus identity. Legacy 262,144/1,048,576-byte defaults are
unchanged; mandatory units that exceed an experimental budget must cause an
explicit refusal/expansion, never silent truncation.

L1 adds explicit agent views without changing default per-skill execution.
The tracked-only disposable workflow fixture, with an explicitly rebuilt index,
produced 108,696 compact-serialized legacy JSON bytes and 81,371 agent JSON bytes.
The earlier local 108,660/80,455-byte observation included an ignored fixture
index; it remains a historical observation, not the reproducible corpus reference.
Exact different source revisions and different target roots remain
distinct and all original excerpt markers survive. These are representation
observations, not native token savings. The internal hook projection keeps raw
evidence and every refusal/strict/sync/exit outcome; new complete diagnostic
receipts require explicit writes. Workflow grouping and task-aware budgets are
still later lots.

## Qualification rules

Keep each attempt's execution, gate evidence, product verdict and operational
classification separate. Preserve refusals and incomplete runs. Complete app
oracles alone cannot qualify handoff, admission or closure. Native performance
must remain `not_evaluated` until the matching whole-workflow criteria pass.
Later comparisons vary one optimization family at a time. Confirmation uses
three independent pairs with alternating order; improvements must satisfy the
manifest thresholds and preserve every applicable governance outcome.
