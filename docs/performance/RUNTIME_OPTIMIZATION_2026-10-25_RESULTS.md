# Runtime optimization: closed results, 2026-10-25

## Decision

The engineering changes and bounded native experiments are implemented and
recorded, but a significant end-to-end improvement is **not demonstrated**.
Four predeclared complete application trials pass their strict workflow and
the same independent twenty-criterion oracle. Forcing compact admission and
hook selectors reduces model responses by 7.9% and delivered dynamic-tool output
by 6.5%, while increasing cumulative input by 14.0%, uncached input by 16.0%
and workflow time by 10.0% in this small comparison. The combined default-adoption
experiment is withdrawn. Ordinary source skill procedures are restored; the
explicit compact APIs, safety controls and independently justified runtime
changes remain available. This is a package/procedure comparison, not a
single-flag causal experiment: other candidate code differs as recorded in
Git. Neither selector's individual effect nor the exclusive effect of their
combination is isolated. The source default withdrawal is a conservative
non-promotion decision, not proof that those flags caused every regression.

The retained interface/transaction work is not promoted as a demonstrated
whole-application speedup. The numerical engineering targets remain unmet in
the available observations. No gate is removed, full authority text truncated,
hard budget raised, or failed sample replaced to improve the numbers.

## Complete native comparison

The sealed protocol orders compact, historical, historical, compact. Every
sample starts with a fresh client and empty private PostgreSQL scope, uses the
same model (`gpt-6.1-sol`, high reasoning, default tier), task, oracle,
whole-authority initial policy, elevated backend, managed network, exact owned
Git adapter and deadlines. Worker phases run sequentially, with a real
coordinator and two fresh native threads per task. No source builds or broad
gates run inside their clocks.

The historical control is `0475392` plus only the three-file hydration
namespace/typed-error correctness fix, local commit `a495957`. It is not the
unmodified release. The compact experimental package is source `6fe160d`.

trials actually select agent format for 22 of 27 hook calls, while using full
admission output for all 35 admissions. The experimental package selects agent
format for all 45 admissions and all 27 hook calls. This comparison measures
the combined procedure/adoption change, not a uniformly full-versus-compact

Two samples per procedure provide descriptive dispersion, not a population
significance test or an SLA estimate. Input is the provider-reported sum across
completed responses; cached inputs are not ordinary-rate inputs. Reasoning is
a reported subset of output and is not added again. The sum of CLI spans
includes lease, process and native transport work; it is not SQL time. Every
task also executes six coordinator CLI calls. Per-call p50/p95, per-response
input p50/p95 and each sample's provider usage remain in the linked structured
evidence. Hidden resident tokens and database transaction/round-trip counts
are unavailable and are not inferred from bytes or CLI counts.

The measured workflow clock includes both native workers and their actual
coordinator. Fixture/package preparation, the final independent oracle and
private database cleanup are outside that clock, consistently across arms.
All four process trees close, private databases are removed, configuration and
frozen controls match, and foreign Git refs/files are preserved. The retained
no-AIDN pilot (1,009.726 s, 30 responses, 993,838 input, 106,926 uncached,
32,780 output, oracle20/20) is a separate calibration, not a paired or enrolled
sample. Ratios against it are descriptive context, not causal improvement.

## Remaining cause and next experiment

Fewer model responses did not produce fewer CLI calls or lower input in this
workload. The comparison observes about94–109 model CLI calls per successful
task and about589–654 seconds in their transport-inclusive spans. It does not
establish that every extra call is caused by a particular projection. These
counts, large provider input per response and unchanged mandatory workflow work
explain why a local output-byte reduction is insufficient; the precise internal
residency and DB decomposition remain unknown.

The next bounded change with the best observed leverage is to qualify the
existing ordered-closure prototype and a staged preparation route: compose
related writes/consultations within one invocation, retain each fresh admission,
revision fence, explicit write intent and full receipt, and preserve the original
deadline and terminal-hook checks. First prove cycle/session digest freshness
and exact partial/refusal behavior on the installed native transport; then run
a fresh equivalent complete-task comparison. Do not bypass the cold authority
policy to fit a budget. Potential global savings are unmeasured, so no numerical
forecast or default promotion is made.
